# 升级、差异更新与回滚

## 网页内更新

新版绘无需启动页，直接使用默认浏览器。关闭最后一个绘网页后释放端口，刷新与切到后台不会退出。

1. 右上角新版本提示可关闭，也可从设置 → 版本更新检查。
2. 点击提示或设置中的更新，先显示新版说明。关闭弹窗或点击暂不更新，不会下载或修改程序。
3. 点击确认更新并重启后，自动下载指定 GitHub 正式版本，核对发布的 SHA256，全部文件暂存校验后才替换。
4. 程序在后台退出、更新并重新启动，使用原目录与原端口，当前页面自动恢复。对话和设置保留，未发送的草稿也恢复。
5. 更新中可以收起弹窗，任务继续。程序不会在正在生成时直接安装；确认前先停止生成或等待附件处理完成。

下载或校验失败时仍运行旧版，可重试；替换失败会回滚并重新启动旧版，网页显示原因。若浏览器被强制结束或系统崩溃，重开绘.exe；不要清空浏览器存储或 .hui-update 备份。

## 迁移没有网页更新功能的旧版（只需一次）

1. 设置 → 版本更新，或打开 [Releases](https://github.com/Hxxdsk/hui/releases)。2.2.0 起可用 `hui-upgrade-v版本-windows-x64.zip`；首次安装用完整包。
2. 把升级包解压到旧目录**之外**，保留 hui-update.exe、apply-update.mjs 和 hui-update-data ZIP。
3. 关闭原绘启动器。运行 hui-update.exe，选择包含绘.exe、app、runtime 的旧版根目录。
4. 数据包通常自动识别。先检查差异，再开始升级。完成后从原目录启动绘.exe。

## 保留与更新

| 内容 | 行为 |
|---|---|
| 程序、界面、EXE、图标、文档 | 按 SHA256 比对，只写不同文件 |
| Node、Python、npm 依赖 | 当前升级保留；以后仅实际改变的文件进入升级包 |
| SQLite、CSV、索引、tokenizer | 当前沿用；以后数据变化仅携带相应差异文件 |
| PixAI 模型与下载缓存 | 升级器不删除或覆盖，继续复用 |
| app/user-data 中的 API 设置和 Key | 保护，不更新，不进入升级备份 |
| app/data/user_dict.json | 用户词典保护，不覆盖 |
| 浏览器聊天、Tag、前缀 | 不清理浏览器；保持同一浏览器、原地址，或导入导出文件 |

这是按**文件**差异更新，不是大文件内部的二进制补丁。某个依赖确有变更时只更新对应文件，不整目录删除。

## 完整性与回滚

升级前检查目标程序已关闭、版本兼容、路径安全、文件长度和 SHA256。全部解压校验通过后才备份、替换；重复点击不会重复写入同哈希文件。

备份与事务保留在旧目录 `.hui-update/任务ID/`，只包含被修改的程序文件，不复制整套模型。写入失败自动回滚；成功后也可点击“回滚上次升级”。回滚会恢复该次改动的程序文件，请避免之后手工改这些文件。

断电或强制结束时，保留该目录。确认升级助手已退出后，删除残留的**单个** `.hui-update/update.lock` 文件，再启动助手恢复。检查提示上次中断时选择回滚，然后重试。旧文件被占用时先关闭占用进程；不要删除备份来修复。

更新器不强制结束其他程序，拒绝降级、损坏包、非法路径和目录联接穿越。过早版本请用完整包配合设置备份迁移。

## 发布者生成差异包

先完成便携构建，再用上一正式版 release-manifest.json：

```powershell
node scripts/build-releases.mjs --baseline previous-release-manifest.json
```

核心程序始终带入，目标同哈希文件跳过；依赖、词库等大资源只有与基准不同才带入。首个公开版基于现有 2.2–2.4 的稳定资源做核心升级。未包含资源继续保留；如果从更早版本跨越了资源格式变更，请按相应版本说明迁移或使用完整包。

后续发布清单会累计标记自首个支持版本以来变化过的运行资源，之后即使资源不再改变也继续纳入升级包；目标已有相同哈希则跳过。因此可以跨过中间版本升级，不遗漏先前新增的必要资源。
